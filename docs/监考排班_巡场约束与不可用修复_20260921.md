# 监考排班 · 巡场约束 + 不可用时段修复（2026-09-21）

用户反馈三条：
1. 有一部分老师设置了不可用时间，但依然被分配了监考任务
2. 巡场老师在所在的考试区间是不参加监考的
3. 巡场老师也需要统计时长

---

## 一、复现与根因（第 1 条）

排班器本身的硬约束是对的（实测：不可用老师 0 分钟、无违规）。
问题出在**导入环节两处静默失效**：

| 现象 | 根因 |
|---|---|
| 老师 CSV 列名写成「不可用时间」，整列被忽略 | 旧代码只认死列名 `不可用时段`（`row.get("不可用时段","")`）→ 静默返回空 |
| 时段写成整天 `2026-10-08~2026-10-08` | 两端都解析成当天 00:00 → **零长度区间**，等于无限制 |
| 时段写成 `2026-10-08 08:00~12:30`（结束只写时刻） | `_parse_dt('12:30')` 抛错 → 导入直接失败（虽然是可见的，但体验差） |

## 二、修复内容

### 1) 解析层（`_parse_dt` / `_parse_ranges`）
- 分隔符放宽：`~ ～ 〜 至 到 — –`（全角波浪号是中文输入法高发项）
- 多段分隔放宽：`| 、 , ， ; ；` 与换行
- 结束时间只写时刻 → 自动沿用开始日期
- 只写一个日期（`2026-10-09`）或 `A~A` → 视为**整天**（00:00 ~ 次日 00:00）
- 结束早于开始 / 起止完全相同（非整天）→ **抛错并指明是第几行、哪位老师**，绝不静默忽略
- `_parse_dt` 兼容全角 `：／`、中英混排 `2026年10月8日`、连续空白

### 2) 列名别名（`_pick` + `_AL_*` 别名组）
- 姓名：姓名/名字/老师/教师
- 不可用：**不可用时段/不可用时间/不可用/请假时段/请假时间/请假**
- 必用：必用时段/必用时间/必用/必须参与时段/必须参与时间
- 巡场：巡场人员/巡场/巡场老师/巡场教师/巡场人/楼道监督员
- 参与：是否参与/是否参加/参与/参加
- 科目/日期/开始/结束/考场/监考人数/班级名称/容量人数/标题 同样有别名
- `_require_columns` 改为「别名组命中任一即通过」

### 3) 不再静默（`_check_unknown_columns` + `on_warn`）
三个 loader 都接收 `on_warn` 回调（GUI 传 `self._log`，CLI 传 `print`）：
- 导入后打印：考试 N 场（其中 M 场有巡场）/ 老师 N 人（其中 U 人填了不可用时段）
- 若老师表里出现含「不可用/请假/必用/参与」等关键词但**未被识别**的列 → 明确告警
- 考场表里出现考试表没有的科目 → 告警（原本会静默丢弃）
- 某场考试在考场表里没有任何考场 → 告警
- 一人没填不可用时段时会提示「若确实填了请检查列名」

### 4) 巡场约束（新增硬约束，第 2 条）
- `Scheduler.patrol_busy`：巡场人 → 其巡场场次的时间区间列表
- `W_PATROL = 100000`：巡场期间被排监考 = 硬违规
- 贪心初始解、`_teacher_hard`、`_report` 三处同步
- 巡场人**不必**出现在老师名单里（校领导等）；只有在名单里的人才受此约束
- `feasibility_check` 把「本场巡场且在老师名单里」的人从可用人数中扣掉，并给出「方案② 调整巡场」建议

### 5) 巡场时长统计（第 3 条）
- `_report` 新增 `ptime`（巡场分钟）、`n_patrol`（巡场场次）、`patrol_not_in_pool`
- 巡场时长 = 所巡场次考试时长（整段）
- `_teacher_rows` 输出：`room_sessions / monitor_min / patrol_sessions / patrol_min / total_min / rooms`
- `老师时长统计.csv` 列变为：
  `姓名, 监考场次, 监考时长(分钟), 巡场场次, 巡场时长(分钟), 总时长(分钟), 涉及教室`
- 只巡场不监考的人（校领导）也出现在统计里
- 均衡指标（总时长极差）只考核监考部分——巡场由用户指定，程序无法调整

### 6) GUI 同步
- 导入时把告警写进日志；摘要栏显示不可用人数与巡场名额
- 「老师时长统计」表新增 3 列（监考时长/巡场场次/巡场时长）
- 「约束检查」显示巡场冲突次数、巡场安排、不在老师名单的巡场人
- 缺口报告加「其中巡场 N 人」

### 7) 其他
- 修 `print_schedule` 里未同步的 4 元组解包（有违规时会崩）
- `demo_data()` 加了巡场：语文巡场「姜校 杨校」（不在池），数学巡场「周菁」（在池）
- 示例模板改成自洽可跑（7 位老师，2 场考试，语文 2 考场 + 数学 1 考场）

## 六、顺带修复：软目标压过硬约束（严重）

测试「把 W_BALANCE 调大能否更均衡」时发现 W_BALANCE=10 会出现 3 处硬违规。

**根因**（三重叠加）：
1. `solve()` 中 `self.hard_sum += delta`，而 `delta` 是 `after - before`，**包含了软代价的变化量**
   → 软权重一大，硬违规计数就被污染、彻底失真；
2. `best` 快照按 `hard_sum + 软代价` 比较，hard_sum 失真 → 选优失效；
3. `_balance_cost` 用平方和（随人数线性增长），量级轻易超过硬权重 100000
   → 退火宁可破坏硬约束去换均衡。

**修复**：
- `hard_sum` 只累加硬约束增量 `d_hard`；软代价单独计算
- 软代价归一化：`_room_cost` / `_balance_cost` 均除以人数，量级与数据规模解耦
- `best` 选优改为**字典序** `(hard_sum, 软代价)`
- 新增**贪心初始解兜底**：最终结果绝不会比贪心初始解更差

**验证**：W_BALANCE 0.2→500、W_ROOM 2000→2000000，硬违规恒为 0。

> 教训：软硬权重混进同一个标量做增量更新是定时炸弹——用户一调参就静默出错，
> 与本轮用户报的第 1 条属于同一类问题（静默失效）。

## 七、均衡目标改为「总时长（监考+巡场等权）」（10:14 用户要求）

**需求**：监考时长与巡场时长权重一样，尽量让每位老师总时长接近。

**改动**：
- `Scheduler.__init__` 预计算 `self.ptime`（每位老师的巡场分钟，常数，不影响增量更新）
- 新增 `_total_minutes(name) = ttime + ptime`
- `_balance_cost` 改为对**总时长**求方差；`_greedy_init` 的均衡启发也改用总时长
  → 巡场多的人自动少排监考
- `_report` 新增 `balance`（总时长极差）、`balance_monitor`、`balance_patrol`、`total_min/max`
- CLI / GUI / 使用说明的文案同步

**真实数据效果（同一批数据）**：

| 指标 | 改前（仅监考均衡） | 改后（总时长均衡） |
|---|---|---|
| 总时长极差 | 210 分 | **90 分** |
| 总时长范围 | 540~690 | **540~630** |
| 硬违规 | 0 | 0 |

90 分已接近理论下限：总时长 18240 分 ÷ 30 人 = 608 平均，按 60 分钟粒度最大不可能低于 630；

## 八、放弃「少换教室」→ 改为「自习岗」均衡（10:23 用户要求）

**需求**：不打破现有规则（硬约束 + 总时长均衡），进一步牺牲「少换教室」，要求老师「自习」与监考的情况尽量均衡。
（导出表里单人考场显示为 `自习\n姓名`，即 need=1 的岗 = 「自习岗」）

**改动**：
- `W_ROOM` 默认改为 **0**（不再追求少换教室）
- 新增 `W_SELF = 3000`：自习岗分配不均的惩罚
- `Scheduler.self_task_ids`（need==1 的任务）+ `n_self[name]` 计数，
  在 `_greedy_init` / `_apply_replace` / `_undo_replace` / 交换分支 / `_rebuild_from_assign` 五处增量维护
- `_soft_cost()` = 教室代价 + 总时长均衡 + 自习均衡（三者都按人数归一化）
- `_report` 新增 `n_self` / `balance_self` / `self_min` / `self_max`
- 统计与导出新增「自习场次」列；CLI/GUI/使用说明文案同步

**真实数据效果**：

| 指标 | 改前（少换教室优先） | 改后（自习均衡优先） |
|---|---|---|
| 自习岗分布 | 0~3 场（极差 3） | **每人 1~2 场（极差 1，即数学下限）** |

实测 W_SELF 从 300 到 100000 结果都一样（已是下限），默认 3000 足够。

## 九、修复导入时的 GBK 编码报错（11:05 用户报障）

**现象**：`'utf-8' codec can't decode byte 0xd0 in position 0: invalid continuation byte`

**根因**：老师在 Excel/WPS 里打开模板改完后「另存为 CSV」，中文 Windows 默认存成 **GBK/ANSI**；
我们按 `utf-8-sig` 读 → 报错。0xD0 正是 GBK 里「姓」的首字节（`姓` = D0 D5），
即文件开头是表头「姓名」。

**修复**：新增 `_read_text(path, on_warn)`，按 **BOM → UTF-8 → GB18030（GBK/GB2312 超集）→ Big5**
依次尝试，自动转换并在日志里提示「已按 GB18030 自动识别」；都不行才用 `errors="replace"` 兜底并报警。
三个 loader 全部改为 `io.StringIO(_read_text(...))`（不改变原有的 `with ... as f` 缩进结构）。

**验证**：
- 用真实数据生成 GBK 版本 → 完全复现用户报错 → 修复后正常导入（31 人、8 人不可用、9 场巡场全对），
  端到端排班 0 违规，总时长极差 90 分、自习 1~2 场
- 回归：UTF-8 BOM / 无 BOM UTF-8 / UTF-16 均正常
- 导出仍带 UTF-8 BOM（Excel 双击不乱码）

> 注意：`codecs.BOM_UTF32_LE` 是 `BOM_UTF16_LE` 的前缀，检测顺序必须 UTF-32 在 UTF-16 之前，
> 否则 UTF-32 文件会被误判。
